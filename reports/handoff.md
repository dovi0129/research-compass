## 1. 지금 어디까지 되어 있는가

기존 구현(데이터 감사 → 정제 → BGE-M3 임베딩 → FAISS 검색 → 재정렬기 → 평가 도구)은 동작한다.
검색 기본 경로는 **E(의미검색 + 재정렬)로 확정**됐다(D-023). 작업공간 **로직 계층(D-024)과 화면 `app.py`(D-025, 사용자 검토 반영 D-026)** 가
있고, 실제 모델·자료로 **검색 → 관점 변경 → 필터 → 비교함 → 분야명 탐색 → JSON 내려받기**가 동작함을 확인했다(아래 3.1).
화면 문구에는 명세 절 번호·결정 번호·모듈명·엔진 코드명을 쓰지 않는다 — 그런 정보는 `개발자용` 펼침에만 있다.
**W3(D-027)** 로 제목 근거 비교(`comparison.py`) · 다음 탐색·확인(`nextactions.py`) · 탐색 메모(`memo.py`)가 화면에 붙었고
실데이터 smoke 를 통과했다(아래 3.2).
**W5(D-028)** 는 비교 조건 **UX-L(목록 전용)** 을 `app.py -- --ux l` 로 구현하고 진행 대본·기록 양식·판정 기준·작업 주제 실측을
`reports/ux_study/` 에 준비했다(아래 3.3). **사용자 평가는 참여자를 확보하지 못해 미실시다** — 명세 §17.6 에 따라
수행했다고 보고하지 않으며 사용성 수치를 만들지 않았다. UX-W 의 사용자 효용은 **미확정**이다.
**화면 재설계(D-029, 2026-09-10)** 로 `app.py` 표시 계층을 다시 썼다 — 메인 흐름 8단계·라이트/다크·70/30 결과·비교표 중심.

### 2.1 변경표를 적용하며 **고친 실제 결함** (v2 §17.5 회귀 점검)

v2 §17.5 가 지목한 증분 키 문제가 이 저장소에 **실재했다.** 세 곳을 고쳤다.

| 위반 | 있었던 동작 | 고친 뒤 |
|---|---|---|
| `keep=first` 로 충돌 은폐 | 같은 항목에 다른 라벨이 있으면 **첫 라벨 채택**하고 경고만 출력 | `label_disagreement` 로 보고하고 **그 항목을 채택하지 않음**. 채점 자체를 중단(exit 2) |
| 증분 key 덮어쓰기 | `pool_key_*_incr.csv` 를 매 실행 덮어써 앞 라운드 라벨이 **결합되지 않고 사라짐**(실측: 라벨 113→112건) | key 누적. 같은 `(query_id, item_id)` 가 다른 `record_id` 를 가리키면 **파일을 보존한 채 중단** |
| `item_id` 단독 판정 | 라벨 완료 여부를 `item_id` 하나로 판단 | `(query_id, item_id)` 로 판정. `key_missing` 을 별도 위반으로 탐지 |

추가로 v2 §17.2~17.4 를 반영했다.

- **라벨 출처 명시:** 기존 5개 시트에 `label_source=llm` 컬럼 추가. `label_source_counts()` 로 출처별 건수를 함께 보고한다. LLM 라벨과 사람 라벨을 하나의 정확도로 섞지 않는다.
- **평가 단위에 관점 추가:** 라벨 키가 `(query_id, perspective, record_id)` 다. 원래 주제 라벨이 방법 중심 질의에 재사용되지 않는다.
- **`used_for_selection`:** `--used-for-selection` 플래그. test 분할은 D-020(하이브리드 off) 판정에 쓰였으므로 이 표시가 필요하다.
- **오래된 빈 증분 시트 정리:** 미라벨이 0이면 남아 있던 빈 시트를 비운다(이중 라벨 방지).

회귀 시험 19개 추가 (`tests/unit/test_label_integrity.py`, W-T23).

### 2.2 적용하지 **않은** 것과 사유

- **근거 비교·메모(W3):** `comparison.py`·`memo.py` 가 남았다. 화면에는 두 영역이 `unverified` 상태와 사유로만 보인다 — 자리만 채우는 가짜 표를 만들지 않았다.
- **`data_manifest.json` 의 절대 경로:** 현재 `file_path` 에 `C:\학교\...` 가 들어간다. v2 §14.6 은 **작업공간 스냅샷**에 민감한 로컬 경로를 넣지 말라고 하므로, 메모/JSON 내보내기에서는 반드시 제외해야 한다. 기존 manifest 형식 변경은 감사 보고서가 참조하는 계약이라 변경표에 없는 변경이므로 **별도 결정으로 남긴다.**
- **가중 RRF 재실험:** D-020 에서 채택 실패. v2 §19 "작은 점수 차이를 위해 새 검색 조건을 계속 늘리지 않는다" 와도 부합해 시도하지 않는다.

## 4. 검색 엔진 A/E — **E 채택 (D-023)**

v2 §2.2 의 명명. **Retrieval-A** = BGE-M3 의미검색 단독, **Retrieval-E** = A 후보에 재정렬기 적용(N_r=20).
증분 라벨 38건을 채워 **미라벨 0건**으로 만든 뒤 판정했다.

| 조건 | dev 엄격 P@5 | dev 완화 | test 엄격 | test 완화 | warm 평균/최대 |
|---|---|---|---|---|---|
| A 의미 단독 | 0.44 | 0.96 | 0.40 | 0.92 | 0.13초 / 0.31초 |
| B 어휘 단독 | 0.24~0.28 | 0.76~0.80 | 0.22~0.26 | 0.78~0.82 | — |
| C RRF | 0.36~0.40 | 0.92~0.96 | 0.36 | 0.90 | 0.12초 |
| D RRF + 재정렬 | 0.56 | 1.00 | 0.40~0.50 | 0.78~0.88 | 2.3초 |
| **E 의미 + 재정렬 N_r=20** | **0.56** | **1.00** | **0.44~0.48** | 0.90~0.94 | **2.5초 / 4.13초** |
| E′ N_r=50 | 0.52 | 1.00 | 0.38~0.42 | 0.86~0.90 | 6.5초 / 9.80초 ❌ |

**기본 경로 = E.** dev·test 둘 다에서 엄격 P@5 가 A 를 넘고(하한 기준으로도), 어휘 baseline 을 크게 넘고,
warm 이 5초 이내다. E′ 는 두 분할에서 더 낮고 5초를 초과해 기각했다 (`top_n=20` 유지).

**그러나 "검증됨" 이 아니다.**

1. 라벨이 **LLM 1차뿐**이다. 사람 스팟체크 30건(2/1 경계) 전에는 "검증됨"으로 표기하지 않는다.
   병렬 에이전트 4개는 **평가자 4명이 아니다.**
2. **dev·test 둘 다 `used_for_selection: true`** 다. test 를 보고 E 를 골랐으므로 미사용 검증셋이 남아 있지 않다.
   최종 확인에 **새 질의 5개 이상**이 필요하다(v2 §17.4).
3. dev 의 상승은 사실상 질의 1개(dev05 0.20→0.80)에 의존한다. test 에서 개선 4·악화 2 로 분포가 넓게
   나온 것이 판정의 실질 근거다. test 최상위 질의 2개가 악화한 사실도 함께 남긴다.
4. warm 은 노트북 CPU 단일 환경 측정이다. `U` 라벨로 test 는 구간(0.44~0.48)이다.

### tau — 확정하지 않음

`margin`(= s_sem − p99(q)) 공간이 가장 깨끗하다. 표본 74건 중 `margin < 0` 24건은 **전부 라벨 0**,
관련 41건은 **전부 `margin ≥ 0`**. 그래도 확정하지 않는 이유는 D-019 에 있다: 이 표본에서 `margin ≥ 0` 이
`rank ≤ 100` 과 **완전히 동일한 분할**이어서 두 공간을 구분할 수 없고(표본에 100~200위 항목이 없다),
**순위 층화 표본이라 P(tau) 가 무편향 정밀도 추정치가 아니다.**
v2 §7.3 대로 이 미확정이 **검색·비교함·메모를 막지 않는다.** 다만 전체 관련 집계·추세·저빈도 후보 게이트는 그대로 잠근다.
