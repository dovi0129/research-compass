## 1. 서비스 개요

**한 문장 정의.** 연구주제를 한 문장(또는 요약 문단)으로 넣으면, 한국연구재단 공공데이터(과제정보)에서 **제목 의미가 가까운 지원과제**를 찾아 보여 주고, 그중 몇 건을 골라 나란히 비교하고, 탐색 과정을 메모로 내보내는 **로컬 웹 도구**.

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 연구주제를 잡는 대학원생·연구자, 유사 과제 선행조사가 필요한 사람 |
| 입력 | 연구주제 한 문장 / 연구 요약 문단 / 대상·방법·목표 낱말 / 연구분야 이름 (+ 선정년도·대사업명 범위) |
| 출력 | 제목이 유사한 과제 목록(기본 5, 최대 10), 선택 과제 비교표, 탐색 메모(Markdown·JSON) |
| 실행 형태 | 노트북 단독, `127.0.0.1` 바인딩, 검색 중 외부 네트워크 호출 없음(`HF_HUB_OFFLINE=1`), 텔레메트리 차단 |
| 기술 | Python 3.12 · Streamlit 1.63 · BGE-M3 임베딩(FAISS flat IP) · bge-reranker-v2-m3 재정렬 · pandas · Altair |
| 생성형 LLM | **사용하지 않음** (검색·순위·문장 생성 어디에도) |

## 2. 화면 (기본 조건 UX-W · 작업공간)

### 2.1 한 페이지 골격

화면은 **하나**다. 검색 전후로 골격이 같고, 검색하면 검색 상자 **아래 같은 자리**에 로딩 표시 → 결과가 붙는다. 첫 화면/결과 화면 전환이 없다.

```
[식별 띠]  한국연구재단 공공데이터 활용 — 과제정보 · 선정과제 연구분야          공공데이터 활용 공모전 출품작
Research Compass(단추) | 한국연구재단 지원과제 탐색
┌ 검색 상자 (70%) ─────────────────────────────┐ ┌ 오른쪽 (30%) ──────────────────┐
│ [연구주제 한 문장|요소별 탐색|연구 요약 붙여넣기|연구분야로 찾기] │ │ 검색 전: 수록 데이터 구성        │
│ (첫 검색 뒤) 탐색 관점 [전체 연구주제|방법·접근|대상·문제]   │ │ 검색 뒤: 비교함 + 표시 중인 구성   │
│ [ 연구주제 / 현재 검색문 …                   ] [탐색]  │ └────────────────────────────────┘
│ 선정년도 [▾]  대사업명 [▾]  □ 짧은 제목 제외            │
│ (범위가 결과와 다르면) 이 범위로 다시 탐색               │
└───────────────────────────────────────────────┘
  최근 탐색 칩 → 제목이 유사한 과제 (결과 카드)             ← 검색 상자 아래, 왼쪽 열 안
  선택한 과제 비교 · 탐색 메모 · 데이터 및 검색 정보 · 수치 띠 · 바닥글 · 화면 모드
```

| 요소 | 설명 |
|---|---|
| 식별 띠 | 맨 위 네이비 한 줄. 왼쪽 `한국연구재단 공공데이터 활용 — 과제정보 · 선정과제 연구분야`, 오른쪽 `공공데이터 활용 공모전 출품작`. 기관 로고·CI 없음(사칭 방지) |
| 머리말 | 컴퍼스 마크 + `Research Compass`(**단추 = 기본 화면으로**) · `한국연구재단 지원과제 탐색`. 설명 문장 없음 |
| 기본 화면 | 로고를 누르면 결과·비교함 절을 숨기고 검색 상자가 연구주제 칸으로 돌아간다. 탐색 이력·비교함·메모는 **지우지 않으며** `이전 결과로 돌아가기` 로 복귀. 여기서 다른 문장을 내면 새 연구주제가 된다. 전부 지우기는 `기능 상태 › 작업공간 초기화` |
| 배치 | 머리말 아래 70/30 한 열 블록. 왼쪽 = 검색 상자 + 그 아래 결과 자리(최근 탐색 칩 · 결과 카드). 오른쪽 = 검색 전 **수록 데이터 구성**, 검색 뒤 **비교함 + 표시 중인 N건의 구성**. 그 아래 전폭으로 선택한 과제 비교 → 탐색 메모 → 데이터 및 검색 정보 → 수치 띠 → 바닥글 → 화면 모드. 최대 폭 1320px, 1000px 이하에서 두 열이 세로로 쌓임 |
| 로딩 | 검색 중 스켈레톤과 "검색 중 · …" 진행 표시가 **결과 자리**에 그려지고, 끝나면 같은 자리에 결과가 온다 |
| 수치 띠 | `수록 레코드 11,783` · `선정연도 2023~2025년` · `대사업명 11` · `주관기관명 749` · `연구분야명 (D2) 851`. 사업·기관은 **구별되는 이름의 수**이며 실제 기관 수라고 하지 않는다. 시험 모드(가짜 엔진) 배지가 여기 붙는다 |
| 바닥글 | `한국연구재단 공공데이터 · data.go.kr 3049029 · 15120687 · 스냅샷 … · 색인 YYYY-MM-DD · bge-m3 <rev8> · 공공데이터 활용 공모전 출품작 — 기관의 공식 서비스가 아닙니다`. KISTEP 코드표 ID 는 싣지 않는다 |
| 준비 안 됨 | 정제 데이터·인덱스·모델 revision 이 맞지 않으면 검색을 막고 복구 명령을 보여 준다. **가짜 결과를 표시하지 않는다** |

화면에 넣지 않은 것: 예시 주제 칩(과거 결정으로 제외, 재결정 대상), 인기·최신 항목(가짜), 작업기록 불러오기(새 기능), 기관 로고·CI(사칭), 설명 문장("이 칸은 ~").

### 2.2 검색 상자 — 검색 방식 4개

엔진은 하나다. 방식은 **검색문을 만드는 경로**만 다르며, 어느 방식이든 검색문 하나로 검색 1회를 실행한다. 어느 탭에서 검색해도 결과가 나오면 `연구주제 한 문장` 탭으로 돌아온다(결과를 만든 관점·검색문이 보이는 곳).

| 방식 | 입력 | 실행 |
|---|---|---|
| **연구주제 한 문장** | 검색 전: 연구주제 한 문장 + `탐색`(Enter 가능). 첫 검색 뒤: §2.3 의 관점 줄 + `현재 검색문` | 관점 `전체 연구주제` 로 1회 / 첫 검색 뒤에는 고른 관점으로 1회 |
| **요소별 탐색** | 연구주제 + `대상·맥락` / `방법·접근` / `목표·질문` + 관점 라디오(전체 연구주제 / 방법·접근 / 대상·문제) | 고른 관점으로 **1회**. 요소가 모자라면 안내만 보이고 실행하지 않는다. 연구주제를 바꾸는 경로이기도 하다 |
| **연구 요약 붙여넣기** | 여러 줄 문단(1,000자) | 문단 전체가 연구주제이자 검색문(관점 `full`, 원문 그대로). 임베더 한도 512토큰을 넘으면 **잘라서 검색하지 않고 멈춘다**(토큰 수 표시). 상태 줄은 160자로 줄이고 전체는 툴팁 |
| **연구분야로 찾기** | 문장 → D2 분야명 851개와의 의미 유사도 상위 8개(분류코드 · 체계 연도 · 원문 선정횟수 `(비교 불가)`) | 검색이 아니다. 넣기 단추(검색 전 `연구주제로 넣기` / 검색 뒤 `검색문에 넣기`)는 칸에 넣고 탭을 바꾸기만 한다 — 실행은 사용자. 선정횟수를 비교에 쓰지 않는 이유는 `(비교 불가)` 툴팁에 |

| 공통 | 설명 |
|---|---|
| 검색 범위 한 줄 | `선정년도`(다중) · `대사업명`(다중) · `짧은 제목 제외`. 검색 전후 같은 위젯이라 첫 검색에 적용되고 이후에도 남는다. 범위가 현재 결과와 다르면 그 줄 아래 `이 범위로 다시 탐색`. `연구분야로 찾기` 탭에는 없다 |
| UX-L | `요소별 탐색` 탭이 없다(관점이 없는 조건). 나머지 셋은 같다 |

### 2.3 탐색 관점 · 현재 검색문 (`연구주제 한 문장` 탭, 첫 검색 뒤)

| 요소 | 설명 |
|---|---|
| 탐색 관점 (세그먼트, 검색문 줄 위) | **전체 연구주제**(주제 문장 그대로) / **방법·접근**(방법 요소 + 목표 요소) / **대상·문제**(대상 요소 + 목표 요소). 관점은 검색문을 바꾸는 **제안**이다. 여러 관점을 한꺼번에 실행하거나 결과를 합치지 않는다 |
| 현재 검색문 | 검색에 그대로 들어가는 문장. **직접 수정 가능**. 관점 제안과 다르면 아래에 `직접 수정됨` 칩 + `관점 제안: "…"`. 낱말을 자동으로 넣거나 늘리지 않는다 |
| 탐색 | 검색 1회 실행 → 결과 자리에 로딩 → "검색 완료 · N초" → 결과 |
| 탐색 요소 조정 (접힘) | 대상·맥락 / 방법·접근 / 목표·질문 각 1개, `요소 반영`. 관점 검색문의 재료이자 요소별 제목 표현 비교의 기준. 자동 추출 없음 |
| 요소 없는 관점 | 방법·대상 관점을 요소 없이 고르면 안내와 요소 입력 폼만 보이고 검색은 실행되지 않는다 |

### 2.4 최근 탐색

탐색이 2회 이상이면 최근 5회를 칩으로 표시. 칩을 누르면 **그 결과로 표시만 바꾸고 다시 검색하지 않는다**(오른쪽 구성 패널도 함께 바뀐다). 실행 직후 새 칩이 즉시 나타난다.

### 2.5 제목이 유사한 과제 (결과 목록)

| 요소 | 설명 |
|---|---|
| 절 제목 | `제목이 유사한 과제` + 표시 건수 |
| 상태 줄 | 관점 · 검색문(160자 초과는 줄이고 툴팁) · `N건에서 검색`(범위가 있으면 `전체 N건 중 M건에서 검색 · 범위: …`) · 처리 시간. 칩: `직접 수정됨`, `이전 연구주제의 결과`, `다른 검색 방식으로 실행됨`(재정렬 실패 시) |
| 안내 한 줄 | "제목의 의미만 비교한 결과입니다. 연구내용은 원문에서 확인하세요." |
| 카드 | 순번(최종 표시 순위) · 제목 원문 · 기관 · 선정연도 · 대사업명 · **의미 유사도 0.xxx**(툴팁: 0~1 상대 점수, 정확도·관련성 판정이 아님) · 태그 `짧은 제목`. 백분위·재정렬 점수·막대는 카드에 없다 |
| 비교함에 담기 | 담긴 것은 `✓ 담김` 으로 비활성. 최대 5건 |
| 검색 근거 보기 (팝오버) | **최종 표시 순위**(이 목록의 순서 · 재정렬 점수 순) · **1차 의미검색 위치**(재정렬 전, 11,783건 중 유사도 위치 — 최종 순위와 다를 수 있음) · 의미 유사도 · 재정렬 점수 · 제목 길이 경고 · 원본 행 · 레코드 ID · 스냅샷 · 원본 데이터 페이지 URL. **관련도 기준선 행은 tau 가 확정돼 `기준값 이상/미만` 을 붙일 수 있을 때만** 생긴다(지금은 없음) |
| 더 보기 / 접기 | 기본 5건, +5씩 최대 10건 |
| 빈 결과 | "검색 범위 안에 결과가 없습니다. 범위를 넓혀 보세요." — 빈 칸을 가짜 레코드로 채우지 않는다 |
| 재정렬 실패 | 재정렬기가 실패·시간초과(10초)하면 의미 유사도 순서로 표시하고 경고 `재정렬 미적용 — 의미 유사도 순서로 표시합니다.` 를 띄운다. 엔진 메모는 `검색 상세 정보` 로그에만. 실패를 성공으로 기록하지 않는다 |

### 2.6 비교함 (오른쪽 30%, 스크롤 고정)

| 요소 | 설명 |
|---|---|
| 담긴 과제 | E1, E2 … 번호(선택 순서) · 제목 · 기관 · 연도. 항목 사이 구분선 |
| 지금 보는 결과에 없음 | 다른 검색에서 담은 과제에 태그 표시 (비교함은 검색·관점을 바꿔도 유지) |
| 빼기 | 비교함에서만 제거. 검색 결과에서는 사라지지 않음 |
| 상태별 안내 | 머리 `비교함 N개`. 0건 "비교할 과제를 담아 주세요." · 1건 "한 개 더 담으면 비교할 수 있습니다." · 2건 이상 안내 없음 |
| 중복 방지 | `(source_snapshot_id, record_id)` 로 같은 과제를 두 번 담지 않는다 |
| 표시 중인 N건의 구성 | 비교함 바로 아래. 표시 결과의 선정연도·대사업명 구성(범위 `displayed_results`). 10건 이하는 차트 대신 글 한 줄. 비교함과 한 묶음으로 스크롤 고정 |

### 2.7 선택한 과제 비교

담은 과제가 **2건 이상**일 때 표가 나타난다(0~1건이면 한 줄). 과제가 열, 아래 행이 나란히 놓인다. **모든 값은 원본에 있거나 수록 데이터에서 센 것이다.**

| 행 | 내용 |
|---|---|
| 탐색 관점 | 어느 탐색 관점에서 찾았는지 (여러 검색에서 담았으면 ①② 로 모두) |
| 검색문 | 그때 실제로 검색한 문장 |
| 당시 순위 | 그 검색 결과에서의 표시 순위 |
| 선정연도 | 선정년도 (결측은 `—`) |
| 사업 | 대사업 › 중사업 › 소사업 › 세부사업 (값이 있는 단계만) |
| 기관 | 주관기관명 |
| 원본 위치 | 원본 데이터 페이지 링크 + 원본 행 번호 |
| (접힘) 수록 데이터 기준 참고 | 같은 사업의 수록 레코드(가장 세부 단계 기준 + 연도별) · 같은 기관의 수록 레코드(+ 연도별). "수록 11,783건 중". 아래 한 줄: "수록 레코드 수이며, 연도별 차이는 지원 규모의 증감을 뜻하지 않습니다." |

행 이름 옆 설명문은 없다(표만으로 읽힌다). 의미 유사도는 이 표에 넣지 않는다(검색문마다 기준이 달라 나란히 비교할 수 없음). "과제 수" 대신 "수록 레코드 수"라 쓰고, 연도별 수를 증감 추세로 해석하는 문장을 만들지 않는다.

## 3. 검색 엔진 동작 (채택 조건 E)

1. **질의 정규화** → BGE-M3(revision `5617a9f6…`, CPU) 임베딩. 제목만 임베딩(`title_only_v1`), 기관·연구자·사업명은 임베딩에서 제외.
2. **의미 검색** FAISS flat inner-product, 후보 100건.
3. **어휘 점수**(char n-gram TF-IDF)는 기록·분석용. 하이브리드 결합은 평가에서 기준 미달로 **꺼둠**(`retrieval.hybrid: false`).
4. **상대 점수**: 전체 11,783건 분포에서의 백분위·p99 경계를 계산해 "N건 중 상위 x%" 로 표시(`검색 근거 보기`).
5. **재정렬**: bge-reranker-v2-m3(revision `953dc6f6…`) 로 상위 20건 재정렬, 시간 제한 10초. 실패 시 의미 순서로 후퇴하고 그 사실을 표시.
6. **범위 필터**: 선정년도·대사업명·짧은 제목 제외는 검색 전에 대상 집합을 좁힌다.
7. **관련도 기준값(tau)**: **미확정(`null`)**. 라벨 표본의 정밀도 곡선으로만 정하며, 확정 전에는 "관련 과제 N건" 을 만들지 않고 기준선 행·태그도 붙이지 않는다.
8. 엔진 이름(개발자용): 의미만 = Retrieval-A, 의미+재정렬 = Retrieval-E(기본). 재정렬 실패는 A 로 기록.

**평가 실측**: 엄격 P@5 dev 0.44→0.56(E), test 0.40→0.44~0.48; 완화 P@5 ≈ 0.9. 라벨은 LLM 1차 블라인드 라벨이라 **"검증됨"이 아니며**, 사람 스팟체크 30건이 발표 전 필수로 남아 있다.

## 7. 하지 않는 것 (설계 원칙)

- 초록 등 원본에 없는 텍스트를 생성해 보충하지 않는다. 생성형 LLM 을 검색·순위·문장 생성에 쓰지 않는다.
- 유사도를 정확도·확률·관련성 판정으로 표기하지 않는다. 결과는 "제목이 유사한 과제 / 가까운 검색 결과"다.
- 제목에 낱말이 있다는 사실을 "그 연구가 그 방법을 썼다"로, 없다는 사실을 "연구가 없다"로 바꾸지 않는다.
- 결측을 0 으로 바꾸지 않고, 제목만 같은 행을 병합하지 않으며, "과제 수" 대신 "수록 레코드 수"를 쓴다.
- 코드표에 있으나 D2 에 없는 분야는 "선정 0건"이 아니라 "관측 없음".
- 관점별 결과를 자동 통합(RRF·평균)하지 않는다. 관점 선택만으로 여러 검색을 자동 실행하지 않는다.
- 요약 붙여넣기가 임베더 한도를 넘으면 앞부분만 잘라 검색하지 않고 멈춘다.
- 개별 과제 URL 을 임의로 조합하지 않는다(데이터셋 페이지 링크 + 원본 행만).
- 연구책임자명·연구자번호는 정제 단계에서 제거되어 화면·메모·인덱스 어디에도 없다.
- 사용자 질의·메모를 서버에 저장하지 않는다. 검색 중 외부 호출을 하지 않는다.
- 우리 데이터에 없는 것(인기 검색어, 이용자 수 등)을 화면에 만들지 않는다. 기관 로고·CI 를 쓰지 않는다.
