# W5 — 사용자 작업 비교 (UX-L vs UX-W)

> 근거: `research_compass_workspace_spec_v2.md` §17.6·§17.7 · 결정 D-028
> 갱신: 2026-09-09

## 상태: 준비 완료 · **사용자 평가 미실시**

| 준비 항목 | 상태 |
|---|---|
| 비교 조건 UX-L 구현 (목록 전용 화면) | ✅ `app.py -- --ux l`, 시험 9개 (`test_app.py` 6 · `test_memo.py` 3) |
| 두 조건의 검색 동일성 시험 | ✅ `test_both_conditions_search_the_same_way` |
| 작업 주제 4개 + 연습 1개 (실데이터 실측) | ✅ 아래 3절 |
| 진행 대본·동의 문구·개인정보 규칙 | ✅ `protocol.md` |
| 기록 양식·판정 기준·사후 질문 | ✅ `forms.md`, `record_template.csv` |
| **실사용자 3명 참여** | ❌ **미확보** |
| 사용성 결과·개선 주장 | ❌ **없음** (미실시이므로 어떤 수치도 만들지 않았다) |

**왜 미실시로 남기는가.** §17.6 은 "사용자를 확보하지 못하면 설문·기록 양식만 준비하고 사용자 평가를
수행했다고 보고하지 않는다"고 정한다. 개발자 혼자 두 화면을 써 보고 "UX-W 가 낫다"고 적는 것은
개발자 친숙성 편향 그 자체이므로 하지 않았다. 발표에서 UX-W 의 사용자 효용은 **미확정**으로 말한다.

**실시하려면:** 참여자 3명(대학원생·연구자 우선, 팀원이면 편향 명시) × 40분. `protocol.md` 를 그대로 따르면 된다.
결과는 `records.csv` + `forms.md` 4절 요약표로 남기고, `handoff.md` §3.3 과 `docs/decisions.md` 에 반영한다.

## 1. 두 조건 실행

```powershell
.venv\Scripts\python.exe -m streamlit run app.py --server.port 8781 -- --ux l   # UX-L (목록 전용)
.venv\Scripts\python.exe -m streamlit run app.py --server.port 8782            # UX-W (작업공간, 기본값)
```

`RESEARCH_COMPASS_UX=l` 환경변수도 같은 효과다. 조건 이름은 화면 문구에 나오지 않고 `개발자용` 펼침에만 있다.

## 2. UX-L 이 약한 비교 대상이 아님 (§17.6)

| 기능 | UX-L | UX-W |
|---|---|---|
| 같은 검색 엔진(의미검색+재정렬)·같은 스냅샷·같은 표시 건수(5, 최대 10) | ✅ | ✅ |
| 원문 제목·주관기관·선정년도·대사업명·출처 행 번호 | ✅ | ✅ |
| **검색문 직접 수정 후 재검색** | ✅ `실제 검색문` 칸 | ✅ 관점 옆 `실제 검색문` 칸 |
| 자료 범위 필터 · 탐색 이력 · 점수 분포·구성 통계 | ✅ | ✅ |
| **자유 메모 + Markdown 내려받기** | ✅ | ✅ (구조화 메모와 별도) |
| 분야명 찾아보기 · 자료 전체 구성 · 기능 상태표 | ✅ | ✅ |
| 요소 입력·관점 조절 | — | ✅ |
| 비교함 (최대 10건, 선택 이유) | — | ✅ |
| 제목 근거 비교표 (표현 발견·인용 검증·사용자 검토) | — | ✅ |
| 다음 탐색·확인 제안 / 탐색 메모(MD·JSON) | — | ✅ |

UX-L 의 기능 상태표에는 그 화면에 없는 4개 기능을 싣지 않는다(참여자에게 없는 기능을 광고하지 않기 위해).

## 3. 작업 주제 — 실데이터 실측 (2026-09-09, 노트북 CPU, warm)

주제는 자료의 도메인 분포(학술·인문사회 88%, 이공 포함)를 보고 **미리** 정했고, 아래 수치는 그 주제로
실제 검색을 돌린 기록이다. **결과가 좋은 주제만 남기지 않았다** — 아래 D 처럼 제목만 보면 빗나간 결과가
섞이는 주제를 일부러 남겼다(§17.6 "유리한 성공 예제만 주지 않는다").

| 주제 | 문장 | 상위 5건 의미 유사도 | 상위 1% 경계(p99) | 1위−p99 | 지연 |
|---|---|---|---|---|---|
| 연습 | 대학생 진로 결정 자기효능감 향상 프로그램 | 0.624~0.695 | 0.544 | +0.151 | 4.9s (첫 실행) |
| **A** | 청소년 스마트폰 과의존과 학업 성취의 관계 | 0.578~0.656 | 0.513 | +0.143 | 2.2s |
| **B** | 리튬이온 배터리 열폭주 억제 소재 개발 | 0.555~0.641 | 0.503 | +0.138 | 2.4s |
| **C** | 지역 소멸 위기 대응 주민 참여 거버넌스 | 0.589~0.663 | 0.501 | +0.162 | 1.8s |
| **D** | 딥러닝 기반 의료영상 판독 보조 알고리즘 | 0.569~0.628 | 0.514 | +0.113 | 2.4s |

진행자 관찰(판정이 아니라 대본 준비용 메모):

- **C** 는 상위 5건이 모두 '지방소멸·주민자치' 제목이라 후보를 고르기 쉬워 보인다.
- **A** 는 스마트폰 과의존 제목과 학업소진·교육격차 제목이 섞여 있어 고르는 판단이 필요하다.
- **B** 는 '열전신소재'·'전극 공정'처럼 **주제와 다른 배터리·열 관련 제목**이 섞인다.
- **D** 는 '위성영상 정합'·'단백질 설계'처럼 딥러닝이라는 말만 겹치는 제목이 상위에 온다. 1위−p99 가 가장 작다(+0.113).
- 즉 난이도는 **C < A < B < D** 순으로 어려워 보인다. 이 차이는 실험 결과 해석에서 반드시 함께 적는다.
  주제와 조건의 짝을 교차 배정하는 이유가 이것이다(`protocol.md` 8절).

> 주의: 위 유사도·경계값은 **가까운 정도**일 뿐 관련성 판정·정확도·확률이 아니다. 관련도 기준선(tau)은
> 여전히 미확정이므로 "관련 과제 N건" 같은 집계는 두 조건 어느 쪽에도 표시되지 않는다.

## 4. 실시 전 점검표

- [ ] `.streamlit/config.toml` 의 `client.showErrorDetails = "none"`
- [ ] 두 조건 창을 각각 연습 주제로 1회 검색해 warm 상태로 만들기 (첫 실행은 느리다)
- [ ] 참여자별 시크릿 창 (이전 입력 잔존 방지)
- [ ] 종이 인쇄: 작업 지시문(§17.6 원문), 사후 질문 5개
- [ ] 기록지: `record_template.csv` 사본. **이름·소속·연락처는 적지 않는다**
- [ ] 참여자가 내려받은 메모 파일은 코드명으로 바꿔 저장소 밖 보관
