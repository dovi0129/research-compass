# UX-L / UX-W 사용자 작업 비교 — 진행 대본

> 근거: `docs/research_compass_workspace_spec_v2.md` §17.6·§17.7 · 결정 D-028
> 상태: **양식 준비 완료 · 미실시** (`README.md` 참조). 이 문서는 실시할 때 그대로 읽는 대본이다.

---

## 1. 두 조건

| 조건 | 화면 | 주는 것 | 주지 않는 것 |
|---|---|---|---|
| **UX-L** | 목록 전용 | 검색, 원문·출처 카드, 점수 분포·구성, 탐색 이력, **검색문 직접 수정**, 자료 범위 필터, **자유 메모(내려받기)**, 분야명 찾아보기, 자료 전체 구성 | 관점 조절, 비교함, 제목 근거 비교표, 탐색 메모(구조화) |
| **UX-W** | 작업공간 | UX-L 의 전부 + 요소 입력·관점 조절, 비교함, 제목 근거 비교표, 다음 탐색·확인, 탐색 메모(MD/JSON) | — |

**같게 유지하는 것 (§17.6):** 검색 엔진(재정렬 포함)·원자료 스냅샷·표시 건수(기본 5, 최대 10)·필터·원문 접근·자유 메모.
UX-W 에만 더 좋은 모델이나 더 자세한 원문을 주지 않는다. 시험 `test_both_conditions_search_the_same_way` 가
같은 주제에서 두 조건의 검색문·엔진·결과 순서가 같은지 확인한다.

**UX-L 을 일부러 약하게 만들지 않았다:** 검색문을 직접 고쳐 재검색할 수 있고(`실제 검색문` 칸),
메모를 쓰고 파일로 내려받을 수 있다. 이 두 가지가 없으면 비교가 성립하지 않는다.

## 2. 실행 (진행자 준비, 참여자 도착 전)

```powershell
# 창 1 — UX-L
.venv\Scripts\python.exe -m streamlit run app.py --server.port 8781 -- --ux l
# 창 2 — UX-W
.venv\Scripts\python.exe -m streamlit run app.py --server.port 8782            # 스크립트 인자는 -- 뒤에만 온다
```

- 첫 검색은 모델 적재 때문에 느리다. **참여자 도착 전에 각 창에서 연습 주제로 1회 검색해 warm 상태로 만든다.**
- 두 창 모두 `127.0.0.1` 바인딩. 시연·실험 전 `.streamlit/config.toml` 의 `client.showErrorDetails` 를 `"none"` 으로 둔다.
- 조건을 화면 문구로 알려주지 않는다. 참여자에게는 "화면 1 / 화면 2" 로만 말한다. (조건 이름은 개발자용 펼침에만 있다.)
- 브라우저 탭은 조건별로 따로 열고, 참여자 교체 시 **새 시크릿 창**을 쓴다(이전 참여자의 입력이 남지 않게).

## 3. 개인정보 규칙 (필수)

- 이름·소속·연락처·학번을 **적지 않는다**. 참여자는 `P1`, `P2`, `P3` 코드로만 기록한다.
- 화면 녹화·음성 녹음은 하지 않는다. 진행자 관찰 기록만 남긴다.
- 참여자가 내려받은 메모 파일은 `P1_L_A.md` 처럼 코드로 이름을 바꿔 **저장소 밖**에 보관한다.
  저장소(`reports/ux_study/`)에는 집계표와 익명 인용만 넣는다.
- 참여자가 자기 연구주제를 쓰겠다고 하면 허용하되, 그 문장을 기록에 옮기지 않고 `(참여자 주제)` 로 적는다.

## 4. 구술 동의 (읽어 준다)

> 이 검사는 사람을 평가하지 않습니다. 화면이 쓸 만한지 보는 것이고, 잘 안 되면 그건 화면 문제입니다.
> 이름이나 소속은 적지 않고, 참여자 코드만 씁니다. 녹화·녹음은 하지 않습니다.
> 어느 시점에나 그만둘 수 있고, 그만두어도 아무 불이익이 없습니다. 소리 내어 생각하며 해 주시면 좋지만
> 의무는 아닙니다. 시작해도 될까요?

## 5. 순서 (1인 40분)

| 시간 | 단계 | 진행자가 할 일 |
|---|---|---|
| 0–3분 | 동의·설명 | 위 문구 읽기. 자료가 **제목과 공개 메타데이터만** 있고 초록이 없다는 점을 알린다 |
| 3–6분 | 연습 | 연습 주제로 첫 조건 화면을 3분 만져 보게 한다. 검색·원문 보기·(해당 조건이면) 담기까지만 |
| 6–19분 | 과제 1 | 아래 작업 지시문을 **소리 내어 읽고 종이로도 준다.** 최대 12분, 시간 초과는 초과로 기록 |
| 19–22분 | 과제 1 사후 질문 | `forms.md` 의 사후 질문 5개 |
| 22–35분 | 과제 2 (다른 조건·다른 주제) | 같은 방식 |
| 35–40분 | 과제 2 사후 질문 + 마무리 | 마지막에 "둘 중 어느 화면을 다시 쓰겠는가, 이유는" 질문 |

## 6. 작업 지시문 (명세 §17.6 원문 그대로 · 두 조건 동일)

> 관심 연구주제에 대해 참고할 과제를 고르고, 선택 이유와 아직 확인하지 못한 사항, 다음 확인 행동을
> 정리하세요. 현재 자료로 충분한 후보를 찾지 못하면 그 이유를 남겨도 됩니다.

덧붙이는 말(두 조건 동일하게 읽는다):

> 정리한 내용은 이 화면에서 파일로 내려받을 수 있습니다. 몇 건을 골라야 한다는 정답은 없고,
> 0건도 답이 됩니다.

## 7. 진행자 개입 규칙

- **하지 않는다:** 결과가 관련 있다/없다 말하기, 어느 버튼을 누르라고 지시하기, 좋은 검색문 알려주기,
  참여자가 못 찾은 기능을 먼저 알려주기.
- **한다:** 오류·멈춤 시 복구, 시간 안내(남은 3분), 참여자가 직접 물으면 "화면에서 찾아보시겠어요?" 한 번 되묻고
  두 번째 질문에는 사실만 답한다(예: "그 칸은 검색문을 고치는 칸입니다"). **개입은 전부 기록한다.**
- 자유 메모를 내려받기 전에 **입력 칸 밖을 한 번 클릭**해야 마지막 문장이 파일에 들어간다(화면 안내에도 있음).
  참여자가 잊으면 내려받은 파일에 마지막 문단이 빠질 수 있으므로, 이때는 개입해 알려주고 기록한다.
- 10분 이상 아무 진행이 없거나 참여자가 중단을 원하면 중단한다. **중단·초과도 소요시간에 포함해 기록한다** (§17.7).

## 8. 주제와 조건 배정 (교차)

주제는 `README.md` 의 표에 있다(실측 결과 포함). 같은 참여자에게 같은 주제를 두 번 주지 않는다.

| 참여자 | 과제 1 | 과제 2 |
|---|---|---|
| P1 | UX-L · 주제 A | UX-W · 주제 B |
| P2 | UX-W · 주제 A | UX-L · 주제 B |
| P3 | UX-L · 주제 C | UX-W · 주제 D |
| (P4) | UX-W · 주제 C | UX-L · 주제 D |

- 조건 순서(L→W, W→L)와 주제-조건 짝을 함께 교차한다. 3명이면 P1·P2·P3 를 쓰고 불균형(주제 C·D 가 1회씩)을 기록한다.
- 참여자가 팀원이면 **개발자 친숙성 편향**을 기록에 명시한다(§17.6).
- 참여자가 자기 연구주제를 쓰겠다고 하면 그 과제는 주제 난이도 비교에서 제외하고 별도로 표시한다.

## 9. 실시 후 산출물

1. `record_template.csv` 를 채운 `records.csv` (참여자 코드만)
2. 조건별 관찰 요약 — 원문 근거·오해·작업 부담 (§17.7 7개 항목)
3. 개선이 관측되지 않으면 **"유용성 미확정"** 으로 남기고, LLM·NPU 를 추가하기 전에 흐름 단순화 검토를 먼저 적는다 (§17.7)
4. 결과를 `reports/handoff.md` §3.3 과 `docs/decisions.md` 에 반영
