# 기록 양식 · 사후 질문 · 판정 기준

> 근거: v2 §17.7 (측정할 항목) · §17.6 · 결정 D-028. 상태: **미실시** — 아래 표는 빈 양식이다.
> 숫자를 미리 채우지 않는다. 실시하지 않은 항목에 값을 적으면 그 자체가 명세 위반이다.

## 1. 과제별 기록 (참여자 1명 × 과제 2건)

`record_template.csv` 를 복사해 `records.csv` 로 채운다. 컬럼 뜻은 아래와 같다.

| 컬럼 | 뜻 | 적는 방법 |
|---|---|---|
| `participant_code` | 참여자 | `P1`~`P3` 만. 이름·소속 금지 |
| `order` | 과제 순서 | 1 / 2 |
| `condition` | 조건 | `UX-L` / `UX-W` |
| `topic_code` | 주제 | `A`~`D`, 참여자 본인 주제면 `OWN` |
| `is_team_member` | 팀원 여부 | `Y` 면 개발자 친숙성 편향 기록 대상 |
| `start_hhmm`·`end_hhmm` | 시작·종료 시각 | 분 단위. **중단·시간초과도 포함** |
| `duration_min` | 소요시간 | 종료−시작 |
| `stop_reason` | 종료 사유 | `완료` / `시간초과` / `참여자중단` / `오류중단` |
| `completed` | 작업 완료 | `Y` = 메모에 (a) 고른 과제와 이유 **또는** 근거 부족 사유, (b) 미확인 사항, (c) 다음 확인 행동이 모두 있음 |
| `n_selected` | 고른 과제 수 | 0 도 정상 값 |
| `n_supported` | 근거 있는 선택 수 | 아래 2절 기준으로 진행자가 판정 |
| `n_unconfirmed_noted` | 미확인 사항을 적은 수 | 제목만으로 모르는 것을 스스로 적었는지 |
| `misread_absence` | 미검출을 부재로 오해 | `Y`/`N` — 아래 2절 |
| `overclaim_user` | 사용자가 쓴 근거 초과 주장 수 | 메모 문장 기준 |
| `overclaim_system` | 화면이 만든 근거 초과 문구 수 | 화면 문구 기준. **사용자 것과 합치지 않는다** |
| `interventions` | 진행자 개입 횟수 | 7절 규칙 위반 없이 한 개입도 모두 |
| `burden_1_5` | 부담 (사후 질문 4) | 1 낮음 ~ 5 높음 |
| `reuse_1_5` | 다시 쓸 것 같은가 (사후 질문 5) | 1~5 |
| `notes` | 관찰 메모 | 인용은 익명. 참여자 주제 문장은 옮기지 않음 |

**분모 규칙 (§17.7):** `n_selected = 0` 인 과제는 근거 있는 선택 비율을 **100% 로 계산하지 않고 "분모 없음"** 으로 둔다.
집계표에서 `n_supported / n_selected` 는 `n_selected > 0` 인 과제만 모아 계산하고, 0건 과제 수를 따로 적는다.

## 2. 판정 기준 (진행자가 메모 파일을 보고)

### 2.1 근거 있는 선택 (`n_supported`)

선택 이유가 **제목과 화면에 표시된 공개 메타데이터**(주관기관·선정년도·대사업명)로 지지되면 1건으로 센다.

| 예 | 판정 |
|---|---|
| "제목에 '디지털 치료제'가 있어 우리 방법과 같은 계열로 보인다 — 내용은 확인 필요" | 지지됨 |
| "2025년 과제라 최신 동향에 가깝다" | 지지됨 (연도는 화면에 있는 값) |
| "이 과제는 노인 대상 RCT 를 했을 것이다" | **초과** (제목에 없는 내용) |
| "유사도 0.62 라서 관련 있다" | **초과** (점수를 관련성 판정으로 씀) |

### 2.2 미확인 사항 인식 (`n_unconfirmed_noted`) · 부재 오해 (`misread_absence`)

- 제목에 표현이 **없는 것**을 "그 연구가 없다 / 아무도 안 했다 / 그래서 우리가 새롭다"로 쓰면 `misread_absence = Y`.
- "제목만으로는 방법을 알 수 없어 원문을 봐야 한다"처럼 적으면 `n_unconfirmed_noted` 에 센다.
- 사후 이해 질문(3절 Q2·Q3)의 답도 같은 기준으로 본다.

### 2.3 잘못된 확정 주장 — 출처를 분리해 센다

| 구분 | 무엇을 세는가 |
|---|---|
| `overclaim_user` | 참여자가 **직접 쓴** 문장 중 근거를 넘는 주장 (예: "연구 공백이다", "동일 연구다") |
| `overclaim_system` | **화면·내려받은 파일이 만든** 문구 중 근거를 넘는 것 (예: 미검출을 부재로 읽히게 쓴 문장) |

`overclaim_system` 이 1건이라도 나오면 그 문구를 그대로 기록하고 화면 문구 수정 대상으로 올린다.
이 둘을 합쳐 하나의 "오류율"로 보고하지 않는다 (§17.7).

### 2.4 성공/실패 판정 금지 규칙

- **작업시간이 줄었어도 근거 없는 판단(`overclaim_*`·`misread_absence`)이 늘면 성공으로 결론내리지 않는다.**
- 3명 규모는 사용성 탐색이다. 비율 차이에 통계적 의미를 붙이지 않고, 관측한 사건을 그대로 적는다.
- 조건 간 차이가 불명확하면 **"유용성 미확정"** 으로 적는다.

## 3. 사후 질문 (과제마다, 같은 문장으로)

1. 방금 한 작업에서 **가장 답답했던 순간**은 언제였습니까?
2. 화면에 "제목에서 확인되지 않음"(또는 제목에 그 표현이 없음)이라고 나오면, 그건 무엇을 뜻한다고 생각하십니까?
   *(이해 확인 — 정답: 제목만으로는 알 수 없다는 뜻. "그런 연구가 없다"는 오해)*
3. 결과 목록의 1위가 나머지보다 **더 관련 있다는 뜻**입니까?
   *(이해 확인 — 정답: 제목이 더 가깝다는 뜻이고 관련성 판정이 아니다)*
4. 지시받은 정리(고른 이유·미확인 사항·다음 행동)를 만드는 데 든 **수고**는 1~5 중 어디입니까? 무엇이 특히 번거로웠습니까?
5. 이 메모를 지도교수 면담이나 팀 논의에 **그대로 가져갈 수 있겠습니까?** 부족한 것은 무엇입니까? (1~5 + 이유)

마지막 과제 후 한 번만: **두 화면 중 다시 쓰겠는 쪽은 어디이고, 그 이유는 무엇입니까?**
