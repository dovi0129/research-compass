## P1. 과학기술표준분류 코드표 대조 — ✅ **완료** (결과: `reports/p1_crosswalk.md`, D-009~D-010)

> 전체 일치율 12.81% 로 게이트 미달. KISTEP 체계 내(D2 의 13%)에서는 98.2% 로 통과.
> D2 의 87% 는 다른 분류체계라 참조표가 없다. 아래는 원래 계획이며 결과 판정은 D-009 참조.

<details><summary>원래 계획</summary>

**전제:** P0-2 승인. 미승인 시 이 단계를 건너뛰고 D-006 A안으로 간다.

**문제 재확인:** D2 의 선정횟수 최소값이 1이다. 0건 분야가 한 행도 없다.
D2 는 *선정 실적이 있는 851개 분야*만 담은 목록이고, **한 번도 선정되지 않은 분야는 관측 자체가 불가능하다.**

**해결:** KISTEP 표준분류 전체 소분류 코드(2,807행)와 D2(851행)의 차집합을 구한다.

```
전체 소분류 코드 (KISTEP)  −  선정 실적이 있는 코드 (D2)  =  선정 0건 분야
```

**작업 순서**

1. `data/raw/` 에 KISTEP CSV 확보. `ingest.register` 로 해시·인코딩 기록
2. **코드 정합성 검증** — D2 의 851개 코드가 KISTEP 소분류코드에 몇 % 존재하는지 확인
3. **분류체계 버전 확인** — D2 는 2025-08-25 스냅샷, KISTEP 은 20251231판. 개정으로 폐지·신설된 코드 구분
4. 차집합 도출 및 `capabilities.json` 재판정

**통과 조건 (하나라도 미달이면 이 축을 포기하고 A안으로 회귀)**

- [ ] D2 코드의 **95% 이상**이 KISTEP 소분류코드에 존재
- [ ] 미매칭 코드 각각의 사유가 설명됨 (개정 폐지 / 표기 차이 / 수준 불일치)
- [ ] 두 자료의 분류체계 개정 버전이 동일하거나, 차이가 문서화됨
- [ ] 차집합 결과가 `evidence_refs` 로 원본 행까지 추적 가능

**미달 시:** "선정 0건" 주장을 하지 않는다. 억지로 매칭하지 않는다. (명세 4.3-4)

**성공 시 얻는 것**

- FR-04 가 제출안 문구("탐색이 적은 인접 연구영역")에 실제로 부합
- D-007 의 변별력 문제 동시 해결 — 0건 분야는 동률이 아니라 명확한 구분선
- 발표에서 "데이터가 말하지 않는 것까지 확인했다"는 서사 확보

## P2. G2 — 검색 엔진 (P0·P1 과 독립 · 🔶 **파이프라인 완성**)

**완료:** `prepare` (11,783건 정제, 보안과제 5건 제외, 짧은 제목 523건 표시) ·
`embedding` (L2 정규화, 벡터 검사) · `retrieval` (FAISS IndexFlatIP + NumPy 참조 구현) ·
`baseline` (char n-gram TF-IDF) · CLI `prepare`/`build-index`/`search` · 단위 테스트 16개 추가

**완료(추가):** 실제 BGE-M3 인덱스 로컬 빌드 (약 20분, D-016) · 평가 질의 15개 고정 · `make-eval-pool`/`evaluate` 구현

**남은 것:** 라벨링(사람) → tau 결정, cold/warm 응답시간 실측

**확인된 제약:** 클라우드 환경에서 `huggingface.co` egress 차단(403). 실모델 인덱스는 로컬에서만 빌드 가능.
FAISS ↔ NumPy 참조 구현 최대 오차 4.47e-08 로 T-09 통과.


**대기 없이 지금 시작할 수 있는 유일한 큰 덩어리다.** P0 답변을 기다리며 진행한다.

1. `prepare` — ProjectRecord / FieldRecord 정제. 개인식별 컬럼(연구책임자명·연구자번호) 제외, 보안과제 `Y` 5건 격리
2. `embedding` — BGE-M3 dense, revision 고정, L2 정규화. **과제명만** 사용 (`title_only_v1`)
3. `retrieval` — FAISS `IndexFlatIP` + NumPy 참조 구현. 필터 적용 후 순위 계산
4. `baseline` — char n-gram TF-IDF (2~5)
5. `cli search` 구현

**이 데이터 특유의 확인 항목**

- 과제명 **10자 미만 521건**(`동아법학`, `당국사보` 등 학술지 지원 과제)의 검색 품질을 별도 지표로 분리 측정
- 제목만 같은 행 388건이 검색 결과에서 어떻게 보이는지 확인 (병합 금지, 표시 중복만 관리)
- 사업명 추가 여부는 **비교 실험 후에만** 결정 (명세 6.2)

**통과 조건**

- [ ] 동일 입력·환경에서 순위 재현
- [ ] FAISS 와 NumPy 참조 구현이 허용 오차 내 일치 (T-09)
- [ ] 필터 적용 집합에서 정확한 Top-K (T-10)
- [ ] cold / warm 응답시간 실측 기록

## P3. G3 — 분석·후보 (P1 결과 반영)

1. **연도 분포** — D1 선정년도 축. 2023·2024·2025 **3개 포인트뿐**임을 화면에 명시.
   차트 제목은 `다운로드한 자료 내 선정연도별 수록 분포`. 성장률·증가 분야 문구 금지
2. **관련 분야** — D2 분야명 독립 임베딩. "개별 과제의 공식 분류가 아님" 문구 고정 노출
3. **후보 규칙 재설계** — D-007 대응

   | P1 결과 | 후보 규칙 |
   |---|---|
   | 성공 | 1순위 = 선정 0건 분야(차집합), 2순위 = 저빈도 분야. 두 층을 **명확히 구분 표시** |
   | 실패/미승인 | 하위 25% 단일 규칙 폐기. 비교 집단 크기·기준값·동률 분야 수·통과 비율(41.5%)을 **모두 표시**하고, 후보를 "순위"가 아니라 "검토 목록"으로 제시 |

## P6. 발표 준비 (명세 21.1 — 구현 범위 밖, 별도 트랙)

명세는 PPT 제작을 필수 구현에서 제외했다. 대신 아래를 준비한다.

1. **데모 시나리오** — 실제 파이프라인을 호출하는 질의 3개. 저장된 결과 재생을 라이브처럼 보여주지 않는다
2. **예상 질문 대응표** — 아래가 심사위원이 반드시 물을 지점이다

   | 예상 질문 | 준비할 답 |
   |---|---|
   | "연구지원 추세는요?" | D2 는 선정횟수 컬럼이 1개라 시계열이 없음. D1 선정년도 축으로 3개년 분포만 제시하며, 이를 추세로 부르지 않기로 **설계 단계에서 결정** |
   | "과제와 분야를 어떻게 연결했나요?" | 공식 연결키가 없어 **연결하지 않았음**. 두 축을 나란히 제시하고 임베딩 최근접 코드를 공식 분류로 저장하는 것을 금지 |
   | "연구공백을 어떻게 찾나요?" | (P1 성공 시) 표준분류 전체 대비 차집합 / (실패 시) 선정 실적 있는 분야 중 상대적 하위임을 명시하고 그 이상은 주장하지 않음 |
   | "AI가 지어낸 건 아닌가요?" | 생성형 모델 미사용. 임베딩 유사도 + 원문 통계 + 규칙 기반 설명. 모든 결과가 원본 레코드로 추적 가능 |
   | "정확도가 어떻게 되나요?" | 사람 라벨 기반 P@5 실측치. 코사인 유사도를 정확도·확률로 표시하지 않는 이유 설명 |

3. **캡처 목록** — 정상 결과 화면, 판단 보류 화면, 근거 추적 화면, 데이터 범위 배너
4. **제한사항 슬라이드** — 숨기지 말고 한 장으로 정면 제시. 이것이 "설명 가능성" 주장의 실물 증거다
